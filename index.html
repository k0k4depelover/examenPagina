Qué hace cada método

  • ReporteadorFuncConectar(): abre una conexión ODBC con el mismo DSN que usan Seguridad y el Navegador (EmbutidosS.A). No hay usuario ni contraseña en el código.
  • ReporteadorFuncObtenerTabla("tblproducto"): hace SELECT * FROM tblproducto y devuelve un DataTable.
  • ReporteadorFuncEjecutarConsulta(...): ejecuta cualquier SELECT (por ejemplo, con JOIN a la categoría) y devuelve un DataTable. Los using cierran la conexión solos.
  • ReporteadorFuncObtenerRuta(n): lee rutaReporte de tblreporte usando el parámetro ? (ODBC), para evitar inyección SQL.

using System.Data.Odbc;

namespace CapaModelo_Reporteador
{

    {

        public OdbcConnection ReporteadorFuncConectar()

C# · CapaModelo_Reporteador/ClsSentenciasReporte.cs
using System;
using System.Data;
using System.Data.Odbc;

namespace CapaModelo_Reporteador
{
    // Consultas SQL del Reporteador (solo lectura)
    public class ClsSentenciasReporte
    {
        private readonly ClsConexion _Conexion = new ClsConexion();

        // Todos los registros de una tabla
        public DataTable ReporteadorFuncObtenerTabla(string Tabla)
        {
            return ReporteadorFuncEjecutarConsulta("SELECT * FROM " + Tabla);
        }

        // Cualquier SELECT (por ejemplo con JOIN)
        public DataTable ReporteadorFuncEjecutarConsulta(string Consulta)
        {
            using (OdbcConnection Conexion = _Conexion.ReporteadorFuncConectar())
            using (OdbcDataAdapter Adaptador = new OdbcDataAdapter(Consulta, Conexion))
            {
                DataTable Datos = new DataTable();
                Adaptador.Fill(Datos);
                return Datos;
            }
        }

        // Ruta del .rdlc registrada en tblreporte
        public string ReporteadorFuncObtenerRuta(int NumeroReporte)
        {
            using (OdbcConnection Conexion = _Conexion.ReporteadorFuncConectar())
            using (OdbcCommand Comando = new OdbcCommand(
                "SELECT rutaReporte FROM tblreporte WHERE numeroReporte = ?", Conexion))
            {
                Comando.Parameters.AddWithValue("@numero", NumeroReporte);
                object Resultado = Comando.ExecuteScalar();
                return Resultado == null || Resultado == DBNull.Value ? null : Resultado.ToString();
            }
        }
    }
}

C# · CapaControlador_Reporteador/ClsControladorReporte.cs
using System;
using System.Data;
using System.IO;
using System.Text.RegularExpressions;
using CapaModelo_Reporteador;

namespace CapaControlador_Reporteador
{
    // Reglas del Reporteador: valida lo que pide la Vista y se lo pide al Modelo
    public class ClsControladorReporte
    {
        private readonly ClsSentenciasReporte _Sentencias = new ClsSentenciasReporte();

        public DataTable ReporteadorFuncDatosTabla(string Tabla)
        {
            if (string.IsNullOrWhiteSpace(Tabla) || !Regex.IsMatch(Tabla, @"^[A-Za-z0-9_]+$"))
                throw new ArgumentException("Nombre de tabla inválido: '" + Tabla + "'.");
            return _Sentencias.ReporteadorFuncObtenerTabla(Tabla);
        }

        public DataTable ReporteadorFuncDatosConsulta(string Consulta)
        {
            if (string.IsNullOrWhiteSpace(Consulta) ||
                !Consulta.TrimStart().StartsWith("SELECT", StringComparison.OrdinalIgnoreCase))
                throw new ArgumentException("La consulta del reporte debe ser un SELECT.");
            return _Sentencias.ReporteadorFuncEjecutarConsulta(Consulta);
        }

        public string ReporteadorFuncRutaValida(string Ruta)
        {
            if (string.IsNullOrWhiteSpace(Ruta))
                throw new ArgumentException("No se indicó la ruta del reporte.");
            string Completa = Path.IsPathRooted(Ruta)
                ? Ruta
                : Path.Combine(AppDomain.CurrentDomain.BaseDirectory, Ruta);
            if (!Completa.EndsWith(".rdlc", StringComparison.OrdinalIgnoreCase))
                throw new ArgumentException("El reporte debe ser un archivo .rdlc: " + Completa);
            if (!File.Exists(Completa))
                throw new FileNotFoundException("No se encontró el reporte: " + Completa);
            return Completa;
        }

        public string ReporteadorFuncRutaDesdeBD(int NumeroReporte)
        {
            string Ruta = _Sentencias.ReporteadorFuncObtenerRuta(NumeroReporte);
            if (Ruta == null)
                throw new InvalidOperationException("No existe el reporte número " + NumeroReporte + " en tblreporte.");
            return ReporteadorFuncRutaValida(Ruta);
        }
    }
}

using System;
using System.Data;
using System.Drawing;
using System.Windows.Forms;
using CapaControlador_Reporteador;

namespace CapaVista_Reporteador
{
    // Control del Reporteador: un botón que se arrastra a cualquier formulario
    // y se configura en una línea (igual que el Navegador).
    public partial class BtnReporteador : UserControl
    {
        private readonly Button _Boton = new Button();
        private readonly ClsControladorReporte _Controlador = new ClsControladorReporte();
        private string _Tabla;
        private string _Consulta;
        private string _RutaReporte;
        private int _NumeroReporte;
        private string _NombreDataSet = "DsReporte";

        public BtnReporteador()
        {
            InitializeComponent();

            _Boton.Text = "Reporte";
            _Boton.Dock = DockStyle.Fill;
            _Boton.FlatStyle = FlatStyle.Flat;
            _Boton.BackColor = Color.FromArgb(91, 15, 21);
            _Boton.ForeColor = Color.White;
            _Boton.Font = new Font("Segoe UI", 10F, FontStyle.Bold);
            _Boton.Click += (Remitente, Evento) => ReporteadorMetMostrar();
            Controls.Add(_Boton);
            Size = new Size(120, 45);
        }

        // Tabla + ruta del .rdlc (si la ruta va vacía, el botón pide elegir el archivo)
        public void ReporteadorMetConfigurar(string Tabla, string RutaReporte, string NombreDataSet = "DsReporte")
        {
            _Tabla = Tabla;
            _Consulta = null;
            _RutaReporte = RutaReporte;
            _NumeroReporte = 0;
            _NombreDataSet = NombreDataSet;
        }

        // Un SELECT propio (por ejemplo con JOIN) + ruta del .rdlc
        public void ReporteadorMetConfigurarConsulta(string ConsultaSelect, string RutaReporte, string NombreDataSet = "DsReporte")
        {
            _Tabla = null;
            _Consulta = ConsultaSelect;
            _RutaReporte = RutaReporte;
            _NumeroReporte = 0;
            _NombreDataSet = NombreDataSet;
        }

        // Tabla + número de reporte registrado en tblreporte (la ruta sale de la BD)
        public void ReporteadorMetConfigurarDesdeBD(string Tabla, int NumeroReporte, string NombreDataSet = "DsReporte")
        {
            _Tabla = Tabla;
            _Consulta = null;
            _RutaReporte = null;
            _NumeroReporte = NumeroReporte;
            _NombreDataSet = NombreDataSet;
        }

        // Carga y muestra el reporte (lo usa el clic y también se puede llamar desde el formulario)
        public void ReporteadorMetMostrar()
        {
            try
            {
                string Ruta;
                if (_NumeroReporte > 0)
                    Ruta = _Controlador.ReporteadorFuncRutaDesdeBD(_NumeroReporte);
                else if (!string.IsNullOrWhiteSpace(_RutaReporte))
                    Ruta = _Controlador.ReporteadorFuncRutaValida(_RutaReporte);
                else
                {
                    string Elegida = ReporteadorFuncElegirArchivo();
                    if (Elegida == null) return;   // canceló
                    Ruta = _Controlador.ReporteadorFuncRutaValida(Elegida);
                }

                DataTable Datos = _Consulta != null
                    ? _Controlador.ReporteadorFuncDatosConsulta(_Consulta)
                    : _Controlador.ReporteadorFuncDatosTabla(_Tabla);

                using (FrmVisorReporte Visor = new FrmVisorReporte(
                    "Reporte - " + (_Tabla ?? "consulta"), Ruta, _NombreDataSet, Datos))
                {
                    Visor.ShowDialog(FindForm());
                }
            }
            catch (Exception Excepcion)
            {
                MessageBox.Show("No se pudo cargar el reporte.\n\n" + Excepcion.Message,
                    "Reporteador", MessageBoxButtons.OK, MessageBoxIcon.Error);
            }
        }

        private string ReporteadorFuncElegirArchivo()
        {
            using (OpenFileDialog Dialogo = new OpenFileDialog())
            {
                Dialogo.Title = "Seleccione un reporte";
                Dialogo.Filter = "Reportes RDLC (*.rdlc)|*.rdlc";
                return Dialogo.ShowDialog() == DialogResult.OK ? Dialogo.FileName : null;
            }
        }
    }

e) Preguntas que te pueden hacer

¿Por qué 3 capas?
Para separar responsabilidades: si cambia la base de datos solo toco el Modelo; si cambia la pantalla o el visor (RDLC → Crystal) solo toco la Vista. Cada capa se puede reutilizar y probar por separado, y el botón se reutiliza en cualquier formulario con una línea.
¿Qué hace cada capa?
Modelo (ClsConexion, ClsSentenciasReporte): habla con MySQL por ODBC, ejecuta el SELECT y devuelve un DataTable; lee la ruta de tblreporte. Controlador (ClsControladorReporte): valida (nombre de tabla con Regex, solo SELECT, que la ruta exista y sea .rdlc) y pide los datos al Modelo. Vista (BtnReporteador, FrmVisorReporte): el botón y la ventana; solo habla con el Controlador.
¿Qué es un RDLC y qué es ReportViewer?
El .rdlc (Report Definition Language Client-side) es un XML con el diseño del reporte: campos, tabla, encabezado y pie. ReportViewer es el control de Microsoft (NuGet Microsoft.ReportingServices.ReportViewerControl.Winforms) que toma ese diseño + los datos, lo dibuja y permite imprimir, exportar a PDF/Excel/Word, hacer zoom y buscar.
¿Procesamiento local o de servidor?
Local (ProcessingMode.Local): el reporte se procesa en la misma PC con los datos que le pasa el programa; no hace falta un servidor. Remoto sería con SQL Server Reporting Services (archivos .rdl publicados en un servidor), que no usamos.
¿Qué es el DataSet del .rdlc y por qué debe llamarse igual?
Es la lista de campos que el reporte espera (<DataSet Name="DsReporte"> con sus <Fields>). En código se le entrega el DataTable con new ReportDataSource("DsReporte", Datos): el ReportViewer une ambos por nombre. Si no coinciden: A data source instance has not been supplied…
¿Cómo evitas la inyección SQL?
El nombre de tabla se valida con una Regex (solo letras, números y _), las consultas propias solo se aceptan si son SELECT, y la búsqueda en tblreporte usa un parámetro ? (ODBC) en lugar de concatenar el número.
¿Para qué sirven tblreporte y tblaplicacionreporte?
tblreporte es el catálogo de reportes (número, nombre único, ruta del archivo, fecha): así la ruta no queda fija en el código y se puede cambiar desde la BD. tblaplicacionreporte liga cada reporte con la aplicación de Seguridad a la que pertenece (por ejemplo «Productos» → reporte 1).
¿Qué cambiarías para usar Crystal Reports?
Instalar SAP Crystal Reports for Visual Studio + runtime, diseñar un .rpt y en la Vista cambiar ReportViewer por CrystalReportViewer (ReportDocument.Load + SetDataSource). Modelo y Controlador quedan igual.

Antes del paso 2: ¿qué es el IdModulo? (y por qué «Inventario»)

⏱ 3 min de lectura · 📍 Concepto clave de Seguridad, léelo aunque tengas prisa

En una frase

El IdModulo no es un inventario de nada y no crea nada: es solo el número de una fila de la tabla tblmodulo. Un módulo es un área de la empresa (Producción, Inventario, Ventas, Seguridad) que agrupa pantallas. Seguridad usa ese número como parte de la «dirección» de los permisos: rol + módulo + aplicación.

La jerarquía de Seguridad

El sistema de Embutidos de Calidad S.A. se organiza como un edificio: el módulo es el piso (un área de la empresa), la aplicación es una oficina de ese piso (una pantalla, por ejemplo «Productos») y el permiso es la llave que tiene cada rol para esa oficina (qué botones puede usar).

¿Por qué el INSERT tiene idRegistroBitacora = 0?

Porque idProducto es AUTO_INCREMENT: el número lo genera MySQL y el Navegador no lo tiene en el momento de escribir la bitácora, así que pone 0. En UPDATE y DELETE sí sale el id real, porque el registro ya existía.

La bitácora va en la MISMA transacción

El cambio y su fila de bitácora se guardan juntos o no se guarda ninguno. Si falla cualquiera de los dos (por ejemplo, la bitácora), se hace rollback y el producto no se guarda. Así nunca hay un cambio sin auditar ni una auditoría de algo que no pasó. Es la atomicidad de ACID.

Preguntas de análisis (respuestas cortas)

📍 Léelas en voz alta una vez

¿Qué es el IdModulo (y el IdAplicacion)?

Son llaves de Seguridad, no datos del negocio. IdModulo es una fila de tblmodulo: un área del sistema (1 Producción, 2 Inventario, 3 Ventas, 4 Seguridad). IdAplicacion es una fila de tblaplicacion: una pantalla dentro de ese módulo (por ejemplo «Productos»). Los permisos (tblrolmoduloaplicacion) se guardan por rol + módulo + aplicación, y el Navegador los busca con los dos números que recibe en NavegadorMetConfigurar. «Inventario» no crea ningún inventario: solo dice en qué área vive la pantalla. Más detalle en ¿Qué es el IdModulo?.

¿Qué es el Navegador?

Un control de usuario de WinForms reutilizable: una barra de 14 botones que da un CRUD completo sobre cualquier tabla de MySQL sin programar formularios. Arma los campos leyendo la estructura de la tabla y aplica la seguridad del sistema (permisos por rol y bitácora).

¿Qué hace NavegadorMetConfigurar y qué son sus 3 parámetros?

NavegadorMetConfigurar(Tabla, IdModulo, IdAplicacion). Tabla es el nombre exacto en MySQL (qué se enseña y se edita). IdModulo e IdAplicacion son el módulo y la aplicación de Seguridad (2 Inventario, Productos) y sirven para buscar los permisos del rol. Si el formulario ya está cargado arma el CRUD al momento; si no, lo hace en OnLoad.

¿Cómo sabe qué campos poner en el formulario?

Lee el esquema: ClsEsquema (capa Modelo) usa GetSchema("Columns") de ODBC e INFORMATION_SCHEMA para sacar columnas, tipos, longitudes, NULL, PK y FK (también intenta detectar el autoincremento, pero el driver ODBC de MySQL no entrega ese dato, así que la PK sale editable). Con eso ClsCrudFormulario crea cada control: FK → ComboBox, DATE → DateTimePicker, TINYINT(1) → CheckBox y el resto TextBox. Las validaciones salen de los mismos metadatos.

¿Cómo se integra con Seguridad?

En tres cosas. (1) Sesión: usa el usuario que entró por el Login de Seguridad; sin sesión avisa y deja en gris los 4 botones de permisos. (2) Permisos: consulta tblrolmoduloaplicacion con los roles del usuario, el módulo y la aplicación. (3) Bitácora: cada INSERT, UPDATE y DELETE queda en tblbitacora con el idUsuario. Todo pasa por CapaControlador_Seguridad, y la conexión es el DSN de ClsConexion de Seguridad.

¿Por qué salen botones en gris?

Porque el rol del usuario no tiene ese derecho (derInsertar, derEditar, derEliminar o derImprimir = 0) para ese módulo y esa aplicación, porque no hay sesión o porque los IDs configurados no son los correctos. Solo afecta a Ingresar, Modificar, Eliminar e Imprimir; los otros 10 no cambian datos y siempre están activos. Se evalúa una sola vez, al abrir el formulario.

¿Permisos por usuario o por rol?

Seguridad tiene los dos: por usuario (tblusuariomoduloaplicacion, pantalla "Asignación Aplicación Usuario") y por rol (tblrolmoduloaplicacion, "Asignación Aplicación Perfiles"). El Navegador solo lee los de rol y combina todos los roles del usuario: basta que uno lo permita. Los de usuario se ignoran; es una mejora pendiente.

¿Qué es la bitácora y por qué va en una transacción?

Es el registro de auditoría: quién (idUsuario), qué acción, en qué tabla, qué registro, el detalle, la IP y la fecha y hora. Se escribe en la misma transacción que el cambio (ClsTransaccion): si algo falla se hace rollback de los dos. Así nunca queda un cambio sin auditar ni una auditoría de un cambio que no pasó (atomicidad).

¿Qué capas tiene y por qué no referencia a CapaVista_Seguridad?

MVC en 3 capas. Vista (CapaVista_Navegador): el control, el formulario dinámico ClsCrudFormulario, la cuadrícula ClsCrudGrid y el coordinador ClsCrudCoordinador. Controlador (CapaControlador_Navegador): validaciones y controladores. Modelo (CapaModelo_Navegador): esquema, ClsRegistros (INSERT, UPDATE y DELETE parametrizados) y transacciones. CapaVista_Seguridad ya referencia al Navegador; si el Navegador la referenciara a ella habría una dependencia circular y no compilaría. Por eso solo usa CapaControlador_Seguridad.

¿Qué usa el botón Consultar?

El componente Consultas (FrmConsultasSimples). Se agrega un filtro con Campo, Operador (=, <>, >, <, >=, <=, Contiene, Comienza con, Termina con) y Valor. Al hacer doble clic en un registro devuelve su PK y el Navegador filtra la cuadrícula a ese registro. Es un ejemplo de integración entre componentes.

¿Por qué no imprime?

Imprimir depende del componente Reporteador, que es de otro equipo y todavía no está integrado (falta acordar qué parámetro recibe además del código de aplicación). El botón existe, está conectado y respeta derImprimir; mientras tanto avisa en lugar de fallar.

¿Eliminar es físico o lógico?

Físico: el Navegador hace DELETE y la fila desaparece, aunque la tabla tenga is_active. El borrado lógico sería UPDATE … SET is_active = 0 y consultar solo lo activo: se conserva el historial y no choca con las FK. Es una mejora que puedes proponer.

¿Qué es ODBC, qué es un DSN y por qué 64 bits?

ODBC es la interfaz estándar de Windows para conectarse a bases de datos mediante un driver. El DSN es una conexión guardada con nombre (servidor, puerto, usuario, contraseña y base), en este caso "EmbutidosS.A", y el código solo conoce ese nombre (fijo en ClsConexion). Los drivers y los DSN son de 32 o de 64 bits; como la DLL es x64, la app tiene que correr en 64 bits (Prefer32Bit = false). Si no, da BadImageFormatException o "DSN no encontrado".

¿Qué pasa si la tabla no tiene PK (o no es autoincremental)?

Sin PK no puede identificar la fila para UPDATE y DELETE: aparece el diálogo "Definir llave primaria" para que marques las columnas que la identifican, y Consultar avisa de que no hay una llave detectable. Si la PK no es autoincremental hay que escribirla a mano: el componente tiene un método que calcula MAX+1 (NavegadorFuncObtenerSiguienteValorLlave), pero la vista no lo usa. Si repites un valor sale "Ya existe un registro con el mismo valor en un campo único."

¿Qué ventajas y desventajas tiene frente a programar un CRUD por tabla?

Ventajas: se reutiliza (una línea de configuración por tabla), todos los CRUD se comportan igual, la seguridad y la bitácora están centralizadas y hay menos código que mantener. Desventajas: la interfaz es genérica, no hay reglas de negocio propias de cada tabla (un precio negativo se acepta) y todo depende de que la base esté bien diseñada (PK y FK reales).

¿Qué debilidades tiene y qué mejoras propondrías?

(1) La tabla y el permiso no están ligados: se puede poner cualquier tabla con los IDs de otra aplicación; convendría asociar cada tabla con su aplicación. (2) Borrado lógico con is_active. (3) Leer también los permisos por usuario. (4) DSN configurable (App.config) en vez de fijo en el código. (5) Integrar el Reporteador. (6) Reglas de negocio además de las de tipo (precio > 0, fecha futura). (7) Recargar los permisos sin reiniciar. (8) Detectar el AUTO_INCREMENT con INFORMATION_SCHEMA (columna EXTRA), porque el driver ODBC de MySQL no lo informa y la PK sale editable.
